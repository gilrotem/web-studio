# Front-end execution stack for premium, motion-rich sites (state as of early November 2026) and delivery as a hand-coded WordPress theme

Research date: 2026-11-09. Target profile researched: a Hebrew-only RTL site on Hostinger shared hosting (LiteSpeed Cache), WordPress 7.1.x, PHP 8.3. Everything below is dated and sourced; items I could not confirm are flagged "unverified" or moved to Gaps. Years on GitHub release pages are often omitted by the page itself; where I inferred the year from ordering I say so.

## Key question 1 — GSAP: current version, what is free, plugin status, 2026 breaking changes, Lenis wiring

### Takeaway
GSAP is at 3.15.1 (tagged 4 Nov 2026), is 100% free including every formerly-paid plugin (SplitText, ScrollSmoother, MorphSVG...) under Webflow, and 2026 brought no breaking changes — only `easeReverse` (3.15.0, April 2026) and the deprecation of `yoyoEase`. Lenis is at 1.3.27 (15 Oct 2026); the documented wiring is `lenis.on('scroll', ScrollTrigger.update)` + `gsap.ticker.add(t => lenis.raf(t*1000))` + `gsap.ticker.lagSmoothing(0)`, with `autoRaf` left at its default `false`.

### Cited Findings
- GSAP npm `latest` is `3.15.1`; license field reads "Standard 'no charge' license" — [npm registry gsap/latest](https://registry.npmjs.org/gsap/latest)
- GitHub tags: 3.15.1 (Nov 4, 2026), 3.15.0 (Apr 13, 2026), 3.14.2 (Dec 12, 2025), 3.14.1 and 3.14.0 (Dec 8, 2025), 3.13.0 (Apr 30, 2025) — [GSAP tags](https://github.com/greensock/GSAP/tags). Note: the GitHub "Releases" page itself shows "There aren't any releases here"; the tag pages carry the notes — [GSAP releases](https://github.com/greensock/GSAP/releases)
- 3.15.0 (released April 13, 2026; authors Jack Doyle and Cassie Evans) introduces `easeReverse`: a tween property that sets a different ease when the playhead moves backward; `true` reuses the forward ease adapted for reverse, or any ease string; GSAP recalculates from the point where direction changed so interrupted tweens stay smooth; works in nested tweens and can be set in timeline `defaults`. `yoyoEase` is deprecated and internally replaced by `easeReverse` ("fully backwards-compatible"). No breaking changes and no plugin changes are listed on the post — [GSAP 3.15 blog](https://gsap.com/blog/3-15/)
- 3.15.1 (tag dated 04 Nov) is bug fixes only, no breaking changes. Core: fixes a 3.15.0 regression where a `stagger` object's `ease` overrode the tween's own ease; ticker no longer skips closely spaced frames (<4ms) on high-refresh displays; paused timeScale changes honor delay; zero-delay `delayedCall()` no longer skipped after pause/resume. ScrollTrigger: fixes stale scroll position restored by `ScrollTrigger.refresh()`; fixes a page jump to top on window resize at a breakpoint when a ScrollTrigger is created inside `gsap.matchMedia()` (a 3.14 regression); `revert()`/`kill()` on matchMedia triggers removes "change" listeners; Firefox history-navigation error with 40+ pinned ScrollTriggers fixed. Flip: `scrollTrigger` inside `Flip.from()` now works. SplitText: line breaks now honored in right-to-left text; Safari line-height on masked SplitText fixed via `vertical-align: top` on mask elements; `.kill()` clears a pending resize timeout; `specialChars` may not be fully honored because of `Intl.Segmenter` pre-splitting (workaround `splitArabicText()` pointed to). ScrollSmoother: no changes — [GSAP 3.15.1 release tag](https://github.com/greensock/GSAP/releases/tag/3.15.1)
- 3.14 headline (Dec 2025) was a new `smooth` option for MorphSVG and the GSAP Demo Hub — [GSAP 3.14 blog](https://gsap.com/blog/3-14/)
- GSAP pricing page: GSAP is "100% free for all users, thanks to Webflow's support"; Webflow's backing lets them "offer the entire GSAP library for free"; plugins listed as included: SplitText, ScrollSmoother, MorphSVG; no paid tiers mentioned; footer "©2026 GSAP - A Webflow Product"; team described as "working full time at Webflow" — [gsap.com/pricing](https://gsap.com/pricing/)
- ScrollSmoother requirements: one content element (default `#smooth-content`) inside a wrapper (`#smooth-wrapper`), wrapper's only child; register `gsap.registerPlugin(ScrollTrigger, ScrollSmoother)` and create the smoother before other ScrollTriggers; `smooth` default 0.8s; `effects: true` enables `data-speed`/`data-lag`; `normalizeScroll` forces scrolling onto the JS thread; smoothing is off on touch-only devices unless `smoothTouch` set; `position: fixed` inside the content element is positioned relative to the transformed content, not the viewport (put fixed elements outside the wrapper); `normalizeScroll` cannot stop the iOS portrait address-bar show/hide, mitigate with `ScrollTrigger.config({ ignoreMobileResize: true })` — [ScrollSmoother docs](https://gsap.com/docs/v3/Plugins/ScrollSmoother/)
- Lenis releases: v1.3.27 (15 Oct) fixes the `lenis` class reappearing after `destroy()` and lets `scrollTo()` accept SVG elements; v1.3.26 (05 Aug) respects reduced-motion preference; v1.3.25 (26 Jun) anchor links with special chars; v1.3.24 (24 Jun) iOS text selection; v1.3.23/22 (15 Apr) `syncTouch` jitter/accuracy and safer CSS class management. No breaking changes flagged — [Lenis releases](https://github.com/darkroomengineering/lenis/releases) (year inferred as 2026 from ordering)
- Lenis README (1.3.27): documented GSAP integration is `lenis.on('scroll', ScrollTrigger.update); gsap.ticker.add((time) => { lenis.raf(time * 1000); }); gsap.ticker.lagSmoothing(0);` and the instance must be driven either by `autoRaf: true` or manual `lenis.raf(time)`. Option defaults: `autoRaf: false`, `lerp: 0.1`, `duration: 1.2` (ignored when lerp set), `smoothWheel: true`, `syncTouch: false` (unstable on iOS < 16), `syncTouchLerp: 0.075`, `anchors: false`, `overscroll: true`, `autoResize: true`, `respectReducedMotion: true` (disables smoothing and makes programmatic scrolls instant), `prevent: undefined` (function returning true for elements not to smooth), `allowNestedScroll: false`, `autoToggle: false`. Recommended CSS: `import 'lenis/dist/lenis.css'`. Limitations: no CSS scroll-snap (use `lenis/snap`), capped at 60fps on Safari and 30fps in low-power mode, smooth scroll stops over iframes, `position: fixed` may lag on pre-M1 macOS Safari — [Lenis README 1.3.27](https://cdn.jsdelivr.net/gh/darkroomengineering/lenis@1.3.27/README.md)

### Inferences
- Because Lenis scrolls the real window (no transform wrapper), ScrollTrigger needs no `scrollerProxy`; the three-line ticker bridge is the whole integration. Choose Lenis (window-native, lighter) or ScrollSmoother (transform wrapper, `data-speed` effects, built by the GSAP team) — not both.
- The 3.15.1 SplitText RTL line-break fix and `Intl.Segmenter` note matter directly for Hebrew headline splitting: pin `gsap >= 3.15.1` for any Hebrew SplitText work and test `specialChars`/masking in Safari.
- Lenis 1.3.26's `respectReducedMotion: true` default means a `prefers-reduced-motion` user gets native scroll automatically; your GSAP `matchMedia` reduced-motion branch should mirror that.

### Gaps
- GSAP did not publish an official "breaking changes in 2026" list; the absence is inferred from the 3.15.0 post and 3.15.1 tag notes only.
- Lenis release years are not printed on the GitHub page; 2026 is inferred from ordering and the 1.3.26 WordPress-plugin references.
- Lenis's own docs site (lenis.darkroom.engineering) was not fetched; the README on jsDelivr was used as the primary doc.

### Inferences
- Progressive-enhancement tiers for a site built on this stack: (a) use freely with no fallback: `:has()`, container queries, `color-mix()`, OKLCH (OKLCH itself was not returned by the query — see Gaps, but `color-mix()`/relative color being Widely/Newly implies OKLCH syntax is universal), `@starting-style`, popover, `text-wrap: balance`, same-document view transitions (feature-detect `document.startViewTransition`); (b) enhance behind `@supports (animation-timeline: scroll())`: scroll-driven animations — Newly available only since 27 Oct 2026, so Firefox ESR and older Safari still lack it; (c) treat as Chromium/Safari-only enhancement: cross-document view transitions (`@view-transition { navigation: auto }` is harmless where unsupported), `text-wrap: pretty` (fallback is plain wrapping — safe to declare without @supports); (d) do not depend on: `if()`, Speculation Rules (Chromium only; harmless elsewhere).
- Anchor positioning: given the Safari 27 default change (`position-anchor: normal`) and the webstatus/web.dev disagreement, wrap anchor-based UI in `@supports (anchor-name: --x)` and give a JS or static fallback for Firefox ESR. Safari lag: Safari 26 shipped the first version (Sept 2025) but the transform-aware and keyword-renamed version is Safari 27 (Sept 2026), so iOS 26 devices behave differently from iOS 27 on edge cases.
- With `text-wrap: pretty` Limited in Firefox, Hebrew body text should not rely on it for widows/orphans; `balance` is the safer heading tool.

## Key question 3 — WebGL/WebGPU: Three.js, WebGPURenderer/TSL, browser share, OGL, Rive, dotLottie, DPR and render-on-demand

### Takeaway
Three.js is at r187 (30 Oct 2026); WebGPURenderer + TSL is the actively developed path with automatic WebGL 2 fallback, but it is still described as evolving (maintainer-acknowledged r182 performance regressions fixed for r183), so pin versions. WebGPU reaches ~88.6% of global usage (caniuse); iOS Safari supports it from 26.0, Firefox desktop and Android still ship it disabled by default (through 162 and 159 respectively). OGL 1.0.11, Rive canvas 2.49.4, dotlottie-web 0.82.1 (with WebGL/WebGPU backends since May 2026).

### Cited Findings
- three.js releases: r187 (30 Oct), r186 (24 Sep), r185 (01 Jul), r184 (16 Apr). r187: `ProxyNodeMaterial`, `compileAsync()` compiles pipelines in parallel, depth-only render targets, passing both `count` and `dispatchSize` now throws, fixes for scissor test, shader reuse for instanced meshes, array camera depth clearing with reversed depth. r186: `compileComputeAsync()`, `DirectRenderPipeline`, shared depth textures across passes, async `dispose()`, `renderer.debug.onNodeBuilderCreated`, WebXR MSAA, material blend color/alpha, removed top-level side effects for tree-shaking. r185: WebXR for WebGPU, rendering to texture arrays, better uncaptured-GPU-error and WGSL diagnostics, `lighting.enabled`, full `ExternalTexture`, WGSL `inverse()` polyfill, TSL `storageTexture3D`. r184 added `HTMLTexture` — [three.js releases](https://github.com/mrdoob/three.js/releases) (year 2026 inferred from ordering)

### Inferences
- For a marketing site, WebGPURenderer is defensible today because of the automatic WebGL 2 fallback and ~89% native coverage, but the r182/r183 regression history argues for pinning to r187 (or the newest) and measuring both paths. The iOS 26 cut-off means every iPhone on iOS 25 or older (and all Firefox users) hits the WebGL 2 fallback — so the WebGL path must look identical, not be an afterthought.
- Rive version numbers: the canvas package (2.49.x) is well ahead of the webgl package (2.27.x) found in search; prefer `@rive-app/canvas` (or `canvas-lite`) for UI-grade animation unless you need WebGL blending.
- dotlottie-web's vendor-described "1.0 production ready" WebGL/WebGPU backends conflict with the npm `latest` being 0.82.1; treat the GPU backends as pre-1.0 until the registry agrees.

## Key question 7 — Hebrew web font delivery: subsetting, unicode-range, variable fonts, font-display, size-adjust

### Takeaway
Serve a self-hosted variable Hebrew WOFF2 split into Hebrew and Latin subsets with `unicode-range`, inline the `@font-face` in `<head>`, preload only the Hebrew file, use `font-display: swap` for display type and `optional` for body, and generate fallback metrics (`size-adjust`, `ascent-override`, `descent-override`, `line-gap-override`) per font pair against a Hebrew-capable system fallback — then test with real Hebrew text, since metric-harmonization heuristics were designed around Latin.

### Cited Findings
- `unicode-range` does not shrink files; it only tells the browser which subset file to fetch; the size reduction must come from pre-subsetting — [FontCreator subsetting tutorial](https://www.high-logic.com/en/font-editor/fontcreator/tutorials/improve-font-performance-with-character-set-subsetting)
- Google-style CSS defines a separate Hebrew `@font-face` covering the Hebrew block (U+0590-05FF) plus a few punctuation code points — [Open Sans font.css (Debian mirror)](https://sources.debian.org/src/r-cran-bslib/0.9.0%2Bdfsg-3/inst/lib/bsw3/simplex/font.css); Noto Sans Hebrew covers the Hebrew and Alphabetic Presentation Forms blocks — [Google Fonts Noto Sans Hebrew](https://fonts.google.com/specimen/Noto+Sans+Hebrew/about)
- Fontsource ships variable Noto Sans Hebrew (wght 100–900) as WOFF2 with `tech(variations)` in `src`, Hebrew served as a separate subset via `unicode-range`; Heebo variable 100–900 also available — [Fontsource Noto Sans Hebrew variable](https://cdn.jsdelivr.net/npm/@fontsource-variable/noto-sans-hebrew@5.2.8/README.md), [Fontsource Heebo](https://fontsource.org/fonts/heebo/cdn), [Fontsource Noto Rashi Hebrew](https://fontsource.org/fonts/noto-rashi-hebrew/cdn)
- Variable fonts require WOFF2 (browsers lacking WOFF2 also lack variable-font support) — [Walter Ebert](https://walterebert.com/blog/subsetting-web-fonts); subsetting a variable Inter WOFF2 to one page's characters cut it from ~317 KB to 33 KB — [Cloud Four](https://cloudfour.com/?p=6501)
- Heebo (Oded Ezer) and Assistant (The Amirim Project) are OFL sans-serifs supporting niqqud only, with some diacritic/ligature gaps; Rubik's Hebrew "Display" variants are single-style effects, poor for body text, while base Rubik works for mixed Hebrew/Latin — [Awesome Hebrew Fonts](https://github.com/danielrosehill/Awesome-Hebrew-Fonts), [Open Siddur fonts](https://opensiddur.org/help/fonts/)
- web.dev font best practices: preload ignores `unicode-range` and competes with other resources, so use it sparingly and prefer inlining `@font-face` in `<head>`; preconnect both `fonts.googleapis.com` and `fonts.gstatic.com` (crossorigin) if using Google Fonts; `swap` shows fallback immediately but late fonts cause a jump, `optional` limits block to ~100 ms and skips late fonts — mix `swap` for branding, `optional` for body; self-hosting is not automatically faster and requires you to subset and WOFF2-compress yourself; variable fonts pay off only with many weights; use `size-adjust` to match fallback metrics and cut CLS — [web.dev font best practices](https://web.dev/articles/font-best-practices)
- Chrome guidance: `size-adjust` alone is of limited use; pair it with `ascent-override`, `descent-override`, `line-gap-override`; values depend on the specific web-font/fallback pair and weights; Fontaine and Capsize generate them — [Chrome improved font fallbacks](https://developer.chrome.com/blog/font-fallbacks), [Chrome framework tools for font fallback](https://developer.chrome.com/blog/framework-tools-font-fallback)
- W3C CSS mailing list (jfkthame): when a metric used for harmonization is missing and no adjustment is applied, Arabic "will end up tiny in comparison to the English" — the metric-based heuristics are Latin-centric — [public-css-archive 2024Mar/0520](https://lists.w3.org/Archives/Public/public-css-archive/2024Mar/0520.html)
- GSAP SplitText 3.15.1 now honors line breaks in RTL text and fixes Safari line-height on masked elements — relevant to Hebrew kinetic typography — [GSAP 3.15.1](https://github.com/greensock/GSAP/releases/tag/3.15.1)

### Inferences
- For a Hebrew-only site the Hebrew subset is the critical one: preload it (and only it) as `<link rel="preload" as="font" type="font/woff2" crossorigin>`, keep the Latin subset lazy via `unicode-range` for digits/brand names, and drop presentation-form glyphs (U+FB1D–FB4F) unless you render niqqud-heavy text.
- `size-adjust` for Hebrew: compute against a fallback the OS actually has for Hebrew (Windows: Arial/Segoe UI; iOS/macOS: Arial Hebrew/SF Hebrew via system-ui). Tools like Capsize/Fontaine derive from the font's global metrics so they work, but visually verify x-height-equivalent (Hebrew letter height) rather than trusting the number.

The commonly used range `U+0590-05FF, U+200C-2010, U+20AA, U+25CC, U+FB1D-FB4F` is from memory and UNVERIFIED.
- No 2026 source gives Hebrew-specific `font-display` or `size-adjust` guidance; the Hebrew caveats above are inferred from Arabic-focused commentary.
- Whether `font-width`/`wdth`-axis Hebrew variable fonts are available for the family a project chooses was not researched.
