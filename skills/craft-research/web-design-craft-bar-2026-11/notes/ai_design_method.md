## KQ2 — How practitioners run the render–critique–refine loop in 2026

### Takeaway
The consensus loop is: define acceptance criteria and a concrete target first; render each state at two viewports (≈390 and ≈1440 px); screenshot with Playwright MCP, Chrome DevTools MCP or Claude in Chrome; compare against the target (Figma `get_screenshot`, reference image, or a pixel/geometry diff) and produce an element/expected/actual/fix table; cap at about three rounds before a human looks; use a fresh-context reviewer (subagent) rather than the builder to judge. Anthropic's own code-review data shows the fresh-reviewer pattern cuts review rounds measurably.

### Cited Findings
- Anthropic's Claude Code team (Oct 15, 2026; Addy Osmani, Morgan Westlee Lunt, Qing Wang): before a PR exists, Claude runs tests/build/lint and "a second agent reviews the diff in a fresh context"; evidence must include "tests, a build or a screenshot to compare against the design"; UI changes are checked against design guidelines; findings are verified by a separate group of agents and tagged Important/Nit/Pre-existing. Measured: PRs passing after one review-and-fix round rose 65%→78%; those needing five or more rounds fell 8.9%→1.5%; mean reviews to pass 2.08→1.32; merged PRs more than doubled June→Sept while reverts fell >40%. — [claude.dev blog](https://claude.dev/blog/solving-code-review-at-anthropic/)
- Anthropic frontend-design skill instructs "critique with screenshots when possible" and "plan, review, then build" (check the plan for generic defaults before coding). — [SKILL.md raw](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md)
- Mowgli workflow (Sept 24, 2026): screenshot each state at 390 px and 1440 px with Playwright MCP or Claude in Chrome; produce a difference table (element, expected, actual, fix); "cap the loop at three rounds before manual review"; make every state previewable via query param or Storybook; put a screenshot-based definition of done in CLAUDE.md, keep CLAUDE.md under ~200 lines, move larger guidance to `.claude/rules/`. — [Mowgli](https://mowgli.ai/blog/claude-code-ui-design-workflow)
- Figma-to-React loop: agent boots dev server, resizes viewport to the Figma frame, screenshots, calls Figma `get_screenshot` on the same node, compares until they match; screenshots do not expose computed CSS, so use Playwright `evaluate` to read real computed properties. — [Medium: Figma-to-React pipeline](https://medium.com/@aliafsah1988/how-to-turn-claude-code-into-a-figma-to-react-pipeline-that-visually-verifies-its-own-work-030246f600a9)
- Make verification mandatory for all frontend work via `web/CLAUDE.md`; shoot at 1280×800 and 375×812; "writing the acceptance criteria into the prompt is the difference between a screenshot as evidence and a screenshot as decoration." — [qaskills.sh](https://qaskills.sh/blog/claude-code-screenshot-frontend-verification-mcp); [Medium: Giving Claude Code eyes](https://medium.com/@rotbart/giving-claude-code-eyes-round-trip-screenshot-testing-ce52f7dcc563)
- Pixel diffing: Playwright `toHaveScreenshot()` uses pixelmatch and emits expected/actual/diff images; the diff image is what you hand the agent ("paste the diff into Claude Code and ask whether the change was intentional"); typical tolerances 0.5%–2% (`maxDiffPixelRatio: 0.02`). — [Steve Kinney course](https://stevekinney.com/courses/self-testing-ai-agents/visual-regression-as-a-feedback-loop); [Argos guide](https://argos-ci.com/blog/screenshot-testing-guide); [bug0](https://bug0.com/knowledge-base/playwright-visual-regression-testing)
- Geometry over pixels: the Codrops/Diorama piece (Nov 1, 2026, Jakub Otcenas) describes "neuro-symbolic validation": extract design geometry from the design tool to JSON and check browser layout against it arithmetically, "because pixel-diff tolerances can hide 1px drift." Also: "typed sources beat prose"; CONVENTIONS.md as the binding rulebook; "treat a design sheet as a contract, not a picture"; raw hex on a sheet is a design bug. — [Knowledge-base intake of Codrops article](https://github.com/adamforrester/knowledge-base/issues/46) (Codrops page itself blocked: [tympanus.net](https://tympanus.net/codrops/2026/11/01/design-systems-agents/))
- Impeccable's hook returns detector findings "before the agent reports the work done," and v4.8.1 lets the agent self-resolve most findings and escalate only undecidable ones — a gate rather than a loop. — [changelog](https://impeccable.style/changelog)
- Chrome DevTools MCP v1.11 `lighthouse_audit` returning failing audits and DOM nodes inline, and v1.10 `get_css_style`, let the critic read computed styles and perf scores rather than eyeball them. — [releases](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases)
- Tooling for jury-style scoring: Impeccable `critique` is "a scored UX review"; Meng To's skill uses an acceptance checklist, not weights; the Awwwards 40/30/20/10 weighting (Design/Usability/Creativity/Content) appears only in third-party skill docs and was not confirmed against Awwwards. — [Impeccable](https://github.com/pbakaus/impeccable); [AgenticSkills](https://agenticskills.io/skills/build-awwwards-quality-sites); [Awwwards skill listing](https://www.skillsdirectory.com/skills/getedgehq-awwwards-sites) **[weights unverified]**
- Codrops limitation list relevant to the loop: agents' motion timing is unreliable; their accessibility checks are stricter than humans' but less visually compelling; unsupervised output "feels empty." — [knowledge-base intake](https://github.com/adamforrester/knowledge-base/issues/46)

### Inferences
- The best-evidenced gate structure is three-layer: (1) deterministic lint on save (Impeccable detector, Vercel guidelines, axe); (2) measured checks (computed CSS via evaluate, geometry JSON vs layout, Lighthouse, pixel diff with ≤2% tolerance vs reference); (3) a fresh-context LLM critic that only sees evidence (screenshots at two viewports + reduced-motion), scored against a written rubric. Humans look after round three.
- Anthropic's 65→78% first-round pass improvement came from "convergence changes" in code review, not design; it is the only hard number found on loop efficiency and should be presented as analogous, not as a design result.
- Motion must be judged by screencast or trace, not stills — Chrome DevTools MCP's ffmpeg-free screencast (v1.11) is the available instrument; no practitioner write-up describing motion review via screencast was found.

### Gaps
- No published study measuring design-quality lift from N review rounds; the "three rounds" cap is one vendor's practice.
- No source describes a jury-style multi-critic scoring loop for websites with measured outcomes.
- Codrops article full text unavailable; limitations are from a paraphrased intake.

## KQ3 — Workflow structure: design package first vs design-while-building; one builder vs parallel; one direction vs options; Art Director role

### Takeaway
Credible 2026 write-ups converge on "decide the design before code, then build against a concrete target": a short written design package (tokens, type roles, wireframes, ban list, states) precedes building; three distinct directions are compared and one is chosen before the frontend-design skill is applied; building proceeds one screen/state at a time. Parallelism is used for variants on isolated routes/worktrees with a human (or lead agent) choosing; no source documents an "Art Director" agent role with measured outcomes.

### Cited Findings
- Anthropic frontend-design: "Plan, review, then build" — draft a compact token system (4–6 hex colors, type roles, ASCII wireframes, alignment choices, principles), check it for generic defaults, revise, then code; "if a brief specifies a direction, follow it exactly," and "spend boldness in one place." — [SKILL.md raw](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md)
- Mowgli (Sept 24, 2026): step 1 inventory screens and states in plan mode (loading, empty, error, success, offline, destructive confirm); step 2 "compare three distinct directions, then choose one" — directions must differ in typography, palette, density and layout structure "not just color swaps," each with a rationale tied to product and audience; step 3 record tokens, components, ban list, required states and a screenshot-based definition of done in CLAUDE.md; step 4 install frontend-design only after a direction is chosen ("it fills in unspecified details without overriding a direction the brief has pinned down"); step 5 build one screen at a time against a concrete target. No measured outcomes given. — [Mowgli](https://mowgli.ai/blog/claude-code-ui-design-workflow)
- Impeccable: `shape` plans UX before code; `init` writes PRODUCT.md and `document` writes DESIGN.md; `generate` makes variants of a named element; `live` cycles variants in a browser overlay and writes accepted changes back to source. — [GitHub](https://github.com/pbakaus/impeccable)
- Evangeline Ng (May 7, 2026): Claude Code builds each concept as a Next.js prototype on versioned routes (`/proto/v1`, `/proto/v2`) on a feature branch using the project's real components, so the author clicks through options and keeps the ones that work; a "design engineer" subagent first decomposes each screen into a spec (layout, spacing, components, tokens, interaction states); generic subagent templates must be adapted to the team's own tokens. — [Substack](https://evangelineng.substack.com/p/mobbin-mcp-claude-code-generate-prototypes)
- Meng To's skill: set art direction before coding (visual thesis, hero focal asset, type hierarchy, color system, section sequence, motion narrative), then build a complete semantic page, "not just a hero." — [AgenticSkills](https://agenticskills.io/skills/build-awwwards-quality-sites)
- Codrops/Diorama (Nov 2026): separate Drafts pages from Handoff pages; use canvas comments as the steering channel; distill each session into small specialized skills rather than one "super-skill"; tokens stay a versioned package "because they must be identical everywhere"; local patches are signals the system got something wrong; author says they "rely less on agents as the level of abstraction grows, and more on their own thinking and design skills." — [knowledge-base intake](https://github.com/adamforrester/knowledge-base/issues/46); [Codrops listing](https://tympanus.net/codrops/2026/11/01/design-systems-agents/)

## KQ4 — What design leaders and critics say about the quality ceiling of agent-made sites and the craft markers that separate premium from template-grade

### Takeaway
Critics describe the ceiling as "distributional convergence" — the model returns the statistical average of its training set (Inter, violet gradients, shadcn blocks, hero-plus-three-cards) — and locate the way past it in a specific point of view, a subject-derived visual thesis, one spent moment of boldness, disciplined typography, real imagery, and motion with a narrative role. Named limits of agents: unreliable motion timing, visually "empty" unsupervised output, over-strict but un-beautiful accessibility.

### Cited Findings
- Anthropic's own list of tells (see KQ1): single highlighted headline word, all-caps labels, labels above content, cream+serif+terracotta, near-black+acid accent, broadsheet hairlines, SaaS card kit, template chrome, fade-and-slide-up everywhere, hover transitions on every card. Positive markers: hero shows "the subject's most distinctive idea," one or two clearly distinct type families, lines under ~80 characters, rules/eyebrows/numbering only when they carry information, "one orchestrated moment" of motion, active-voice CTAs that name the action. — [SKILL.md raw](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md)
- Impeccable's named defaults: "Inter for everything," "purple-to-blue gradients," nested cards, rounded-square icon above every heading; new checks for widows ("straggler") and unbalanced headings; advisory against hard offset shadows. — [GitHub](https://github.com/pbakaus/impeccable); [changelog](https://impeccable.style/changelog)
- Meng To's anti-patterns: gradient blobs, ornamental bento grids, glass everywhere, stock component layouts, "motion with no narrative role," fake testimonials, logo-wall theater, initials/illustrated heads/generated people presented as real, model-authored SVG/CSS/canvas illustrations; markers of the bar: hero intro sequence + section choreography + word-by-word heading reveals with restrained stagger, ScrollTrigger reserved for scrubbed/pinned sequences, states covered (hover, focus, active, loading, disabled, error, touch, reduced-motion), reduced motion renders final states immediately, split headings keep an unsplit accessible name. — [AgenticSkills](https://agenticskills.io/skills/build-awwwards-quality-sites)
- Codrops/Diorama: hard lines against agent artifacts such as "thick left card borders and random dashed lines"; agents' motion timing unreliable; unsupervised output "feels empty"; a Heron case study (Oct 12, 2026) drew on architectural technical drawings "rather than the typical look of AI products." — [knowledge-base intake](https://github.com/adamforrester/knowledge-base/issues/46); [Codrops AI tag](https://tympanus.net/codrops/tag/ai/)
- Sameness essays (2026): Snoddy attributes it to tools trained on the same components reaching for "Inter type, violet gradients, and shadcn/ui blocks"; Mowgli calls it "distributional convergence"; Kompozy names a feedback loop where creators absorb AI output as "what good looks like"; remedies are a clear audience and point of view, and treating AI output as a structural first draft a designer then styles. — [joshuasnoddy.com](https://www.joshuasnoddy.com/blog/why-ai-websites-look-the-same/); [Mowgli](https://mowgli.ai/blog/claude-code-ui-design-workflow); [Kompozy](https://kompozy.io/guides/the-ai-design-aesthetic); [dev.to GDG](https://dev.to/gdg/why-ai-websites-all-look-the-same-and-how-to-build-something-different-1gan)
- Taste commentary: Designer Fund 2026 survey — half of surveyed designers had shipped AI-generated code to production, and many felt taste matters more as "good enough" gets easier; a Feb 2026 essay argues "taste is the new bottleneck" and critique shifts to "shared calibration"; another expects polish to become table stakes so "restraint becomes the mark of craft." Dive Club episodes in 2026: Brandon Jacoby "Seeing Taste vs. Creating Taste" (Apr 21, 2026), Pablo Stanley "Protecting your creativity in an AI world" (Jul 21, 2026), Stephen Haney "The 2026 AI Design Field Report" (contents not fetched). — [Designer Fund Substack](https://designerfund.substack.com/p/ai-in-design-2026-the-inflection); [designative.info](https://www.designative.info/2026/02/01/taste-is-the-new-bottleneck-design-strategy-and-judgment-in-the-age-of-agents-and-vibe-coding/); [Alphabytes Substack](https://joinalphabytes.substack.com/p/a-guide-to-the-future-of-design-2026); [Dive Club](https://www.dive.club/episodes)
- Nielsen Norman Group on AI prototyping tools: heuristic evaluations found the tools "often produced unpolished, indistinctive visual styles," while "a detailed prompt produced results that closely matched the human-designed version" (article undated in results). Jakob Nielsen (June 2026) criticized a five-tool AI UI study for judging quality via user survey rather than measured performance. — [NN/g AI prototyping](https://nngroup.com/articles/ai-prototyping/); [UX Tigers roundup](https://www.uxtigers.com/post/ux-roundup-20260622)
- Awwwards: no 2026 Awwwards article or conference talk specifically on agent-made sites was found; Awwwards talk listings are undated and general. — [Awwwards talks](https://www.awwwards.com/conferences/talks)

### Inferences
- The craft markers critics and skill authors agree on, in craft terms: Type — one or two deliberate families, a real scale, no widows/unbalanced headings, no all-caps eyebrows or single-word highlights. Composition — a hero built around the subject's most characteristic idea/asset, boldness spent once, rules and labels only where informative, deliberate alignment. Imagery — real or licensed photography, no model-drawn SVG/CSS illustration, no generated people as real. Motion — one orchestrated moment plus action-triggered feedback, choreography with a narrative role, correct reduced-motion fallbacks, timing checked by a human because agents' timing is unreliable. States — all interaction and content states designed and previewable. Performance — guarded WebGL (DPR cap, offscreen pause, poster fallback), Lighthouse-checked.
- The ceiling is less a model limit than an input limit: every source that reports getting past it credits a specific written direction and reference set, not a better model.

### Gaps
- No Awwwards jury member, Pentagram, or Fons Mans statement specifically on agent-made sites was found in 2026 sources.
- Dive Club episode contents not fetched; titles only.
- Codrops full text blocked; craft claims are via paraphrase.

## KQ5 — Reference intake in 2026: building a "level references" set and which libraries for taste vs UX structure

### Takeaway
Practitioners split reference intake into two streams: UX-structure references (Mobbin via MCP, now callable by agents with search_screens/flows/sections and collections) and taste references (Awwwards, Godly, Savee, Cosmos, Are.na, Fonts In Use — human-curated, not agent-callable). ### Cited Findings
